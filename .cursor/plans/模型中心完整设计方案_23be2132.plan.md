# 模型中心完整设计方案

## 一、整体架构设计

### 1.1 模块划分

模型中心分为四个核心模块，形成完整的模型生命周期管理闭环：

```
模型库 → 模型上线 → 模型调度 → 模型监控
  ↑                                    ↓
  └─────────────── 反馈优化 ───────────┘
```

### 1.2 数据流转

- **模型库**：模型资产统一纳管，版本化管理
- **模型上线**：通过审批和检测后进入生产环境
- **模型调度**：生产环境中的模型执行管理
- **模型监控**：实时监控模型运行状态，发现问题并告警

## 二、模块详细设计

### 2.1 模型库（Model Registry）

#### 2.1.1 功能定位

统一资产纳管，解决模型文件满天飞、版本混乱的问题。

#### 2.1.2 页面结构

- **主页面**：`model-registry-page.tsx`（已存在，需增强）
- **模型详情页**：`model-detail-page.tsx`（已存在，需增强）
- **模型编辑页**：`model-edit-page.tsx`（已存在，需增强）
- **模型注册页**：`model-register-page.tsx`（需新建）

#### 2.1.3 核心功能设计

**1. 版本化注册**

- 支持 Staging/Prod 环境标签管理
- 版本号规范：语义化版本（SemVer）
- 版本历史记录和对比
- 版本回退能力

**2. 模型签名（Schema定义）**

- 输入Schema定义：字段名、类型、约束、示例值
- 输出Schema定义：返回结构、类型、说明
- Schema兼容性检查：版本升级时自动检测Schema变更
- Schema可视化展示：JSON Schema编辑器 + 预览

**3. 依赖包管理**

- 依赖包列表：Python包、系统依赖
- 环境自动打包：生成requirements.txt、Dockerfile
- 依赖版本固定：锁定版本号，避免环境不一致
- 依赖冲突检测：自动检测版本冲突

**模型库管理页面（主列表）**

- 环境标签筛选（Staging/Prod）

### 2.4 模型监控（Monitoring）

#### 2.4.1 功能定位

维持服务稳定，在用户投诉前发现模型异常并处理。

#### 2.4.2 页面结构

- **性能监控页**：`performance-monitor-page.tsx`（已存在，需增强）
- **告警通知页**：`alerting-page.tsx`（已存在，需增强）

#### 2.4.3 核心功能设计

**1. 服务性能监控**

- **QPS监控**：每秒查询数，实时曲线图
- **Latency监控**：响应延迟，P50/P95/P99分位数
- **Error Rate监控**：错误率，错误类型分布
- 时间范围选择：实时/1小时/24小时/7天/30天
- 多模型对比：选择多个模型对比性能

**2. 数据漂移监控**

- **PSI检测**：Population Stability Index
- 特征分布对比：当前分布 vs 训练分布
- 漂移阈值配置：PSI > 0.25 告警
- 特征重要性分析：哪些特征漂移最严重
- 漂移趋势图：PSI值随时间变化

**3. 告警通知**

- 告警规则配置：阈值、条件、通知渠道
- 告警记录：历史告警、处理状态
- 通知渠道：邮件、即时通讯（企业微信/钉钉）
- 告警级别：低/中/高/紧急
- 告警聚合：相同告警合并，避免告警风暴

## 三、页面间逻辑关系

### 3.1 模型生命周期流程

```
1. 模型注册（模型库）
   ↓
2. 准入检测（模型上线）
   ↓
3. 发布审核（模型上线）- 调用工作流API
   ↓
4. 部署审核（模型上线）- 调用工作流API
   ↓
5. 部署管理（模型上线）- 创建部署实例
   ↓
6. 调度配置（模型调度）- 配置执行任务
   ↓
7. 监控告警（模型监控）- 实时监控运行状态
```

### 3.2 页面跳转关系

- **模型库** → **模型上线**：点击"发布"按钮，跳转到发布审核
- **模型上线** → **模型调度**：部署成功后，提示创建调度任务
- **模型调度** → **模型监控**：调度详情页可跳转查看监控
- **模型监控** → **模型库**：发现异常时，可跳转查看模型详情

## 五、技术实现要点

### 5.1 工作流集成

- 使用现有工作流API，无需实现工作流引擎
- API调用示例：
  - 发起审批：`POST /workflow/api/v1/xflowable/process/start`
  - 审批通过：`POST /workflow/api/v1/xflowable/task/{taskId}/approval`
  - 审批驳回：`POST /workflow/api/v1/xflowable/task/{taskId}/back`
  - 查询进度：`GET /workflow/api/v1/xflowable/process/instance/history`

### 5.2 图表可视化

- 使用 Recharts 或 ECharts 进行数据可视化
- 监控指标：实时折线图、柱状图
- PSI检测：分布对比图、趋势图

### 5.3 实时数据

- WebSocket 连接用于实时监控数据
- 或使用轮询方式（每5秒刷新）

### 5.4 文件上传

- 模型文件上传：支持大文件分片上传
- 进度显示：上传进度条
