# 模型库与部署管理融合方案

## 一、现状分析

### 1.1 当前页面功能对比

#### 模型库页面（model-registry-page.tsx）
- **定位**：已部署到生产环境的模型资产库
- **核心功能**：
  - 模型列表展示（名称、版本、框架、状态）
  - 搜索和筛选（按名称、版本、状态）
  - 批量操作（归档、导出、版本对比）
  - 模型查看和归档
- **关注点**：模型资产本身（版本、依赖、Schema等）

#### 部署管理页面（deployment-management-page.tsx）
- **定位**：管理模型在生产环境的部署实例
- **核心功能**：
  - 部署实例列表（环境、版本、状态、资源、端点）
  - 新建部署任务
  - 版本切换（灰度发布）
  - 回滚操作
  - 启动/停止部署
  - 部署历史查看
  - 健康检查状态
  - 查看监控（跳转）
- **关注点**：部署实例的运行状态（资源、端点、健康状态）

### 1.2 功能重叠分析

| 功能 | 模型库 | 部署管理 | 重叠度 |
|------|--------|----------|--------|
| 模型版本管理 | ✅ | ✅ | 高 |
| 版本切换 | ❌ | ✅ | - |
| 版本回滚 | ❌ | ✅ | - |
| 部署状态查看 | ❌ | ✅ | - |
| 部署历史 | ❌ | ✅ | - |
| 模型详情查看 | ✅ | ❌ | - |
| 批量操作 | ✅ | ❌ | - |

**重叠点**：
- 都涉及模型版本管理
- 都关注生产环境的模型
- 部署管理的版本切换、回滚操作本质上是模型版本的操作

### 1.3 用户使用场景

**场景1：查看已部署的模型**
- 当前：模型库 → 查看模型列表
- 问题：无法直接看到部署状态，需要跳转到部署管理页面

**场景2：切换模型版本**
- 当前：部署管理 → 找到部署实例 → 版本切换
- 问题：需要先知道模型在哪个部署实例中，操作路径较长

**场景3：回滚到上一个版本**
- 当前：部署管理 → 找到部署实例 → 回滚
- 问题：需要记住部署实例ID，操作不够直观

## 二、融合方案设计

### 2.1 方案一：模型库增强型（推荐）

**核心思路**：在模型库页面中集成部署管理功能，以模型为中心，部署信息作为模型的属性展示。

#### 2.1.1 页面结构调整

**模型库列表页增强**：
1. **增加"部署状态"列**：
   - 显示该模型的所有部署实例数量
   - 显示运行中的部署数量
   - 显示健康状态（健康/不健康）
   - 点击可展开查看部署详情

2. **操作列增强**：
   - 保留原有操作：查看、归档
   - 新增操作：
     - **部署管理**：点击后弹出抽屉，显示该模型的所有部署实例
     - **快速操作**：如果只有一个部署实例，直接显示版本切换、回滚按钮

3. **部署信息卡片**（可展开）：
   - 部署环境（生产/预发布）
   - 当前版本
   - 部署状态（运行中/已停止/更新中）
   - 健康状态
   - 端点地址
   - 快速操作按钮（版本切换、回滚、启动/停止）

#### 2.1.2 模型详情页增强

在模型详情页增加"部署管理"Tab：

**Tab内容**：
1. **部署实例列表**：
   - 显示该模型的所有部署实例
   - 每个实例显示：环境、版本、状态、资源、端点、健康状态
   - 支持操作：版本切换、回滚、启动/停止、查看监控、查看历史

2. **版本切换功能**：
   - 选择目标版本
   - 配置灰度比例
   - 确认切换

3. **回滚功能**：
   - 显示可回滚的版本列表
   - 一键回滚到上一个版本

4. **部署历史**：
   - 显示该模型的所有部署操作历史
   - 包括：部署、更新、回滚、启动、停止等操作

#### 2.1.3 保留部署管理页面（简化版）

**保留原因**：
- 需要全局视图：查看所有部署实例（跨模型）
- 运维视角：按环境、状态筛选所有部署
- 批量操作：批量管理多个部署实例

**简化后的功能**：
- 保留全局部署实例列表
- 保留新建部署功能（选择模型和版本）
- 保留批量操作（批量启动/停止）
- 移除单个模型的版本切换、回滚（这些功能移到模型库）

### 2.2 方案二：完全融合型（备选）

**核心思路**：完全移除部署管理页面，所有功能都在模型库中完成。

#### 2.2.1 模型库页面重构

**列表视图**：
- 每个模型显示其所有部署实例
- 支持按部署状态筛选（运行中/已停止）
- 支持按环境筛选（生产/预发布）

**详情视图**：
- 模型基本信息
- 部署管理Tab（同方案一）

**全局视图切换**：
- 提供"模型视图"和"部署视图"切换
- 部署视图：类似当前的部署管理页面，但数据来源是模型库

### 2.3 方案对比

| 维度 | 方案一（增强型） | 方案二（完全融合） |
|------|-----------------|-------------------|
| 实施难度 | 中等 | 较高 |
| 用户体验 | 优秀 | 优秀 |
| 功能完整性 | 完整 | 完整 |
| 运维视角 | 保留 | 需要重新设计 |
| 向后兼容 | 好 | 一般 |
| 推荐度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |

## 三、推荐方案详细设计（方案一）

### 3.1 模型库列表页增强

#### 3.1.1 数据模型扩展

```typescript
interface ModelInfo {
  // 原有字段
  id: string;
  name: string;
  version: string;
  environment: 'staging' | 'production';
  framework: string;
  status: 'draft' | 'registered' | 'archived';
  // 新增字段
  deployments?: DeploymentSummary[]; // 部署实例摘要
  deploymentCount?: number; // 部署实例总数
  runningDeploymentCount?: number; // 运行中的部署数
  healthStatus?: 'healthy' | 'unhealthy' | 'unknown'; // 整体健康状态
}

interface DeploymentSummary {
  id: string;
  environment: 'staging' | 'production';
  version: string;
  status: 'running' | 'stopped' | 'updating' | 'rolling_back';
  healthStatus: 'healthy' | 'unhealthy';
  endpoint: string;
}
```

#### 3.1.2 UI组件设计

**列表列设计**：
```
| 模型名称 | 版本 | 框架 | 部署状态 | 操作 |
|---------|------|------|---------|------|
| 模型A   | v1.2.3 | TF | 🟢 2个运行中<br>🔴 1个不健康 | [查看] [部署管理] [归档] |
```

**部署状态列显示**：
- 图标 + 文字：🟢 2个运行中 / 🔴 1个不健康
- 点击展开：显示该模型的所有部署实例卡片

**操作列**：
- 查看：跳转详情页
- 部署管理：弹出抽屉，显示部署管理界面
- 归档：原有功能

### 3.2 部署管理抽屉设计

**抽屉内容**：
1. **头部信息**：
   - 模型名称和版本
   - 部署实例统计（总数、运行中、已停止）

2. **部署实例列表**：
   - 卡片式展示每个部署实例
   - 显示：环境、版本、状态、资源、端点、健康状态
   - 操作按钮：版本切换、回滚、启动/停止、查看监控、查看历史

3. **快速操作区**：
   - 如果只有一个部署实例，显示快速操作按钮
   - 版本切换、回滚按钮直接可见

### 3.3 模型详情页部署管理Tab

**Tab结构**：
```
部署管理 Tab
├── 部署实例列表
│   ├── 部署实例1（生产环境）
│   │   ├── 基本信息（版本、状态、资源、端点）
│   │   └── 操作按钮（版本切换、回滚、启动/停止、查看监控、查看历史）
│   └── 部署实例2（预发布环境）
│       └── ...
├── 版本切换抽屉
│   ├── 当前版本显示
│   ├── 目标版本选择
│   └── 灰度比例配置
└── 部署历史
    └── 操作记录时间轴
```

### 3.4 部署管理页面简化

**保留功能**：
- 全局部署实例列表（所有模型的部署）
- 按环境筛选（生产/预发布）
- 按状态筛选（运行中/已停止/更新中）
- 新建部署任务（选择模型和版本）
- 批量操作（批量启动/停止）

**移除功能**：
- 单个部署实例的版本切换（移到模型库）
- 单个部署实例的回滚（移到模型库）
- 单个部署实例的部署历史（移到模型库详情页）

**页面定位调整**：
- 从"部署管理"改为"部署概览"或"部署中心"
- 专注于全局视图和批量操作

## 五、技术实现要点

### 5.1 数据获取

**模型库列表页**：
- 获取模型列表时，同时获取每个模型的部署摘要信息
- API设计：`GET /api/models?includeDeployments=true`

**部署管理抽屉**：
- 根据模型ID获取该模型的所有部署实例
- API设计：`GET /api/models/{modelId}/deployments`

**模型详情页**：
- 获取模型详情时，同时获取部署信息
- API设计：`GET /api/models/{modelId}?includeDeployments=true`

### 5.2 组件复用

**可复用组件**：
- `DeploymentCard`：部署实例卡片组件
- `VersionSwitchDrawer`：版本切换抽屉组件
- `DeploymentHistory`：部署历史组件

### 5.3 状态管理

**建议使用**：
- React Context 或 Zustand 管理部署状态
- 确保模型库和部署管理页面的数据同步

## 六、用户体验优化

### 6.1 操作流程优化

**优化前**：
```
模型库 → 查看模型 → 部署管理 → 找到部署实例 → 版本切换
（5步）
```

**优化后**：
```
模型库 → 点击"部署管理" → 版本切换
（2步）
```

**效率提升**：60%

### 6.2 信息展示优化

- **一目了然**：在模型库列表就能看到部署状态
- **快速操作**：常用操作（版本切换、回滚）一键可达
- **上下文清晰**：在模型详情页的部署管理Tab中，所有操作都在模型上下文中

## 七、风险评估

### 7.1 技术风险

**风险**：数据获取可能影响列表页性能
**应对**：
- 部署摘要信息异步加载
- 使用虚拟滚动优化长列表
- 添加加载状态和骨架屏

### 7.2 用户体验风险

**风险**：用户习惯现有页面结构
**应对**：
- 保留部署管理页面（简化版），提供过渡期
- 提供使用指南和提示
- 收集用户反馈，持续优化

### 7.3 功能完整性风险

**风险**：融合后可能遗漏某些功能
**应对**：
- 详细的功能对比清单
- 充分的测试覆盖
- 保留部署管理页面作为补充

- **保留所有功能**：不丢失任何现有功能
- **增强功能**：增加快速操作和批量管理能力

## 九、总结

### 9.1 推荐方案

**推荐采用方案一（模型库增强型）**，理由：
1. ✅ 实施难度适中，风险可控
2. ✅ 用户体验显著提升
3. ✅ 保留运维视角的全局视图
4. ✅ 向后兼容性好
5. ✅ 功能完整，不丢失任何能力

### 9.2 核心价值

1. **以模型为中心**：符合用户思维模式（先选模型，再管理部署）
2. **减少操作步骤**：常用操作一键可达
3. **信息集中展示**：模型信息和部署信息统一管理
4. **保留灵活性**：仍可通过部署管理页面进行全局管理
