## 1. 数据领域术语

### 1.1 数据集 (Dataset)

**定义**: 用于AI模型训练、评估或应用的结构化数据集合。

**业务含义**:
- 数据集是平台的核心资产,包含特定业务场景下的历史数据
- 每个数据集具有唯一标识符(datasetId)和版本号(version)
- 支持数据集的申请、上传、审核、公开等全生命周期管理

**技术特点**:
- 类型定义: `DatasetType` (src/types/dataSandbox.ts)
- 包含元数据(metadata)、业务对象(businessObject)、组织维度(orgDimension)等属性
- 支持时间范围查询(beginTime/endTime)

**使用场景**:
- 数据广场浏览数据集
- 数据集申请与授权
- 模型训练数据源选择
- 数据集版本管理

**相关接口**: `/datas/page`, `/datas/save`, `/dataApplication/upload`

---

### 1.2 业务实体 (Business Entity / Business Object)

**定义**: 业务领域中具有独立业务意义的数据对象,是对现实业务概念的抽象表示。

**业务含义**:
- 业务实体是数据模型的核心组成部分,代表业务中的关键概念
- 例如:水量、水质、设备、工单等业务对象
- 每个业务实体具有对象层级(objectHierarchy)和所属系统/单元(businessObjectType)

**技术特点**:
- 类型定义: `BusinessObjectType` (src/types/dataSandbox.ts)
- 包含属性:业务实体名称(businessObject)、数据分类(dataType)、数据更新频率(dateDim)
- 支持字段数量统计(propertyCount)

**使用场景**:
- 业务实体管理模块
- 数据集关联业务实体
- 数据目录分类管理
- 业务应用场景标识

**注意事项**: 在代码中,"业务对象"和"业务实体"是同义词,统一使用"业务实体"表述

---

### 1.3 逻辑数据模型 (Logical Data Model, LDM)

**定义**: 描述业务实体及其属性的逻辑结构,独立于物理实现的数据模型。

**业务含义**:
- 逻辑数据模型是业务实体的详细描述,包含实体名称、字段、业务定义等
- 用于标准化数据结构,确保数据一致性
- 包含业务规则(businessRules)和责任部门(responsibleDepartment)

**技术特点**:
- 类型定义: `LogicalDataModel` (src/views/backend-management/data-catalog/logicalMockData.ts)
- 核心属性:实体编码(entityCode)、实体名称(entity)、字段数量(fieldCount)
- 关联数据来源(dataSource)、业务域(businessDomain)

**使用场景**:
- 逻辑数据模型管理
- 数据集元数据定义
- 数据标准化管理
- 数据目录分类体系

**相关API**: `/provider/ailabLogicalDataModel/list`

---

### 1.4 数据分类 (Data Type / Data Classification)

**定义**: 按照业务特性和用途对数据进行的分类标识。

**业务含义**:
- 用于区分不同类型的业务数据(如:水量、电量、污泥、药剂、水质等)
- 便于数据检索和管理
- 支持数据权限控制

**技术特点**:
- 字段名: `dataType`
- 通常与业务实体(businessObject)组合使用
- 支持字典管理,可动态配置分类项

**使用场景**:
- 数据集筛选条件
- 业务实体分类标识
- 数据目录导航
- 搜索过滤条件

---

### 1.5 业务域 (Business Domain)

**定义**: 业务领域的划分,表示数据或模型所属的业务范畴。

**业务含义**:
- 用于组织和分类业务数据
- 支持跨业务域的数据整合和分析
- 便于业务归属管理

**技术特点**:
- 字段名: `businessDomain` / `businessdomain`
- 支持业务域层级结构
- 可配置业务域枚举值

**使用场景**:
- 数据集分类
- 逻辑数据模型归属
- 业务分析主题划分
- 数据治理范围界定

---

### 1.6 元数据 (Metadata)

**定义**: 描述数据本身特征的数据,包括字段名、数据类型、单位、描述等。

**业务含义**:
- 元数据是数据集的"数据字典"
- 提供数据字段的详细说明,便于数据理解和使用
- 支持数据质量管理和数据治理

**技术特点**:
```typescript
metadata: Array<{
  fieldName: string    // 字段名称
  description: string  // 字段描述
  dataType: string     // 数据类型
  unit: string         // 单位
  classTag: string     // 分类标签
}>
```

**使用场景**:
- 数据集详情展示
- 数据探查功能
- 字段映射配置
- 数据质量检查

---

### 1.7 数据目录 (Data Catalog)

**定义**: 组织和管理数据资产的分类体系,包括业务实体、逻辑数据模型等的分层结构。

**业务含义**:
- 数据目录是数据资产的导航系统
- 支持多层级的分类管理(系统/单元、业务实体、数据分类等)
- 便于数据发现和数据治理

**技术特点**:
- 树形结构组织
- 支持编码体系(catalogCode)
- 包含父子关系(parentCatalogId)

**使用场景**:
- 数据目录管理模块
- 业务实体分类
- 数据资产导航
- 数据治理框架

---

### 1.8 组织维度 (Organization Dimension / Org Dimension)

**定义**: 数据所属的组织范围,标识数据的归属和访问权限边界。

**业务含义**:
- 用于数据的多租户隔离
- 支持按组织授权和数据共享
- 便于数据责任管理

**技术特点**:
- 字段名: `orgDimension`, `orgId`, `orgName`
- 支持多组织选择(数组类型)
- 关联组织树结构

**使用场景**:
- 数据集组织归属
- 数据访问权限控制
- 数据申请审批范围
- 跨组织数据共享

## 2. 模型领域术语

### 2.1 模型 (Model)

**定义**: 通过机器学习或规则引擎训练生成的,用于预测、分类或决策的算法实体。

**业务含义**:
- 模型是平台的核心产出物
- 支持机器学习模型、智能体、数据规则模型三大类型
- 每个模型具有版本管理和生命周期状态

**技术特点**:
- 类型定义: `ModelInfo` (src/types/modelManagement.ts)
- 核心属性:模型名称(modelName)、模型类型(modelType)、适用场景(applicableScenario)
- 支持版本号(modelVersion)、版本别名(versionAlias)

**使用场景**:
- 模型广场浏览
- 模型训练与部署
- 模型评估与回测
- 模型版本管理

**相关模块**: model-plaza, model-develop, model-evaluation, model-management

---

### 2.2 模型类型 (Model Type)

**定义**: 模型的分类标识,表示模型的实现方式和应用特点。

**业务含义**:
- **机器学习模型**: 基于数据训练的预测模型
- **智能体**: 具有自主决策能力的智能系统
- **数据规则模型**: 基于业务规则的决策模型

**技术特点**:
```javascript
modelTypeOptions = [
  { value: 1, label: '机器学习' },
  { value: 2, label: '智能体' },
  { value: 3, label: '数据规则模型' }
]
```

**使用场景**:
- 模型创建时类型选择
- 模型列表筛选条件
- 模型功能分类展示
- 审核流程区分

---

### 2.3 模型版本 (Model Version)

**定义**: 模型的迭代标识,记录模型的演进历史。

**业务含义**:
- 支持模型的版本管理和回滚
- 每个版本对应一次训练或更新
- 版本别名(versionAlias)便于业务识别

**技术特点**:
- 字段名: `modelVersion`, `versionAlias`
- 支持版本计数(versionCount)
- 包含发布版本号(published_version)

**使用场景**:
- 模型版本发布
- 模型版本对比
- 模型回滚操作
- 版本历史追溯

---

### 2.4 适用场景 (Applicable Scenario)

**定义**: 模型适用的业务场景或应用领域。

**业务含义**:
- 描述模型的应用范围和适用条件
- 便于用户选择合适的模型
- 支持场景化的模型推荐

**技术特点**:
- 字段名: `applicableScenario`
- 支持多场景标签
- 可配置场景枚举

**使用场景**:
- 模型创建时场景选择
- 模型广场场景筛选
- 模型推荐匹配
- 业务场景分析

---

### 2.5 模型公开状态 (Public Status / Release Status)

**定义**: 模型的发布和共享状态,控制模型的可见性和可用性。

**业务含义**:
- **公开**: 所有用户可见可用
- **私有**: 仅创建者和授权用户可用
- **待审核**: 正在审核流程中

**技术特点**:
- 字段名: `publicStatus`, `releaseStatus`
- 关联审核状态(approvalStatus)
- 影响模型可见范围

**使用场景**:
- 模型发布管理
- 模型访问控制
- 模型广场展示
- 模型共享机制

---

### 2.6 部署状态 (Deployment Status)

**定义**: 模型的部署状态,表示模型是否已部署到生产环境。

**业务含义**:
- **未部署**: 模型仅存在于开发环境
- **已部署**: 模型已发布到生产环境,可提供服务
- **部署中**: 正在部署过程中

**技术特点**:
- 字段名: `deploymentStatus`, `deployStatus`
- 关联部署审核流程
- 支持部署标识(isDeploy)

**使用场景**:
- 模型部署管理
- 模型服务状态监控
- 部署审核流程
- 生产环境管理

---

### 2.7 性能指标 (Performance Metrics)

**定义**: 模型的性能评估指标,用于衡量模型的预测能力。

**业务含义**:
- 评估模型的准确性、效率等关键指标
- 支持模型选择和优化决策
- 便于模型对比分析

**技术特点**:
```typescript
interface PerformanceMetrics {
  inference_latency?: string    // 推理延迟
  accuracy?: string              // 准确率
  mean_squared_error?: number    // 均方误差
}
```

**使用场景**:
- 模型评估报告
- 模型对比分析
- 模型性能监控
- 模型优化决策

---

### 2.8 运行环境 (Runtime Environment)

**定义**: 模型运行所需的技术环境配置,包括编程语言、框架、依赖等。

**业务含义**:
- 描述模型的技术栈要求
- 确保模型可复现和可部署
- 便于环境准备和依赖管理

**技术特点**:
```typescript
interface RuntimeEnvironment {
  python_version?: string       // Python版本
  framework?: string             // 框架(如TensorFlow)
  hardware_recommendation?: string  // 硬件推荐
  dependencies?: {               // 依赖包
    tensorflow?: string
    keras?: string
    pandas?: string
  }
}
```

**使用场景**:
- 模型部署环境准备
- 依赖包管理
- 兼容性检查
- 环境配置文档

## 3. 技术架构术语

### 3.1 服务层 (Service Layer)

**定义**: 业务逻辑封装层,提供可复用的业务服务接口。

**业务含义**:
- 服务层封装复杂的业务逻辑
- 提供统一的服务接口供控制器调用
- 实现业务逻辑与界面展示的解耦

**技术特点**:
- 在前端项目中体现为API调用模块(src/api/)
- 使用axios进行HTTP请求
- 统一的请求拦截和响应处理

**使用场景**:
- 数据集服务(dataset.ts)
- 模型管理服务(modelManage.ts)
- 用户管理服务(user.ts)
- 权限管理服务(role.ts)

**代码示例**:
```typescript
// src/api/dataset.ts
export const getDatasetList = (params) => {
  return http.request({
    url: '/datas/page',
    method: 'post',
    data: params
  })
}
```

---

### 3.2 控制器 (Controller)

**定义**: 在前端架构中,指Vue组件中处理用户交互和业务逻辑的部分。

**业务含义**:
- 控制器负责接收用户输入
- 调用服务层API获取数据
- 更新视图状态和UI展示

**技术特点**:
- 使用Vue 3 Composition API (`<script setup>`)
- 通过ref/reactive管理组件状态
- 使用组合式函数(Composables)复用逻辑

**使用场景**:
- 表单提交处理
- 列表数据加载
- 用户操作响应
- 状态管理协调

**代码示例**:
```vue
<script setup>
import { ref } from 'vue'
import { getDatasetList } from '@/api/dataset'

const tableData = ref([])
const loadData = async () => {
  const res = await getDatasetList(params)
  tableData.value = res.data.records
}
</script>
```

---

### 3.3 组件 (Component)

**定义**: 可复用的UI模块,封装了特定功能的视图和逻辑。

**业务含义**:
- 组件是前端应用的构建块
- 提高代码复用性和可维护性
- 支持组件组合和嵌套

**技术特点**:
- Vue 3单文件组件(.vue)
- 支持props传递和事件发射
- 使用TypeScript进行类型约束

**组件分类**:
- **业务组件**: 特定业务场景的组件(如DatasetCard)
- **通用组件**: 可跨业务复用(如AdvancedSearch、CardInfo)
- **布局组件**: 页面布局结构(如Layout、TopBar)

**使用场景**:
- UI界面构建
- 功能模块封装
- 代码复用
- 组件库建设

---

### 3.4 路由 (Router / Route)

**定义**: 前端应用的页面导航机制,管理URL与组件的映射关系。

**业务含义**:
- 路由定义应用的页面结构
- 支持页面跳转和参数传递

- 路由元信息(meta)存储权限等配置

**路由结构**:

```typescript
{

      path: 'dataset-management',

      component: () => import('@/views/data-sandbox/dataset-management/index.vue'),
      meta: { title: '数据集管理' }
    }
  ]
}
```

**使用场景**:
- 页面导航配置
- 权限路由守卫
- 动态菜单生成
- 路由参数传递

### 3.5 状态管理 (State Management / Store)

**定义**: 应用级的数据状态管理机制,实现跨组件的数据共享。

**业务含义**:
- 集中管理全局状态
- 实现组件间数据共享
- 支持状态持久化

**技术特点**:
- 使用Pinia作为状态管理库
- 模块化Store设计
- 支持TypeScript类型推导

**Store模块**:
- `userStore`: 用户信息和登录状态
- `menuStore`: 菜单和权限状态
- `datasetStore`: 数据集操作状态
- `themeStore`: 主题配置状态

**代码示例**:
```typescript
// src/store/modules/datasetStore.ts
export const useDatasetStore = defineStore('dataset', {
  state: () => ({
    currentDataset: null,
    datasetList: []
  }),
  actions: {
    setCurrentDataset(dataset) {
      this.currentDataset = dataset
    }
  }
})
```

**使用场景**:
- 用户登录状态管理
- 当前选中数据管理
- 全局配置共享
- 跨组件通信

### 3.6 中间件 / 拦截器 (Middleware / Interceptor)

**定义**: 在请求/响应流程中执行的预处理和后处理逻辑。

**业务含义**:
- 统一处理认证Token
- 统一错误处理和提示
- 请求参数预处理
- 响应数据格式化

**技术特点**:
- Axios请求拦截器(request interceptor)
- Axios响应拦截器(response interceptor)
- 路由导航守卫(navigation guard)

**实现示例**:
```typescript
// 请求拦截器
http.interceptors.request.use(config => {
  if (localStorage.getItem('token')) {
    config.headers.Authorization = localStorage.getItem('token')
  }
  return config
})

// 响应拦截器
http.interceptors.response.use(response => {
  if (response.data.code !== 200) {
    ElMessage.error(response.data.message)
  }
  return response.data
})
```

**使用场景**:
- Token自动注入
- 统一异常处理
- 请求日志记录
- 响应数据转换

---

### 3.7 分页 (Pagination)

**定义**: 数据列表的分页查询和展示机制。

**业务含义**:
- 支持大数据量的高效加载
- 提升用户体验和性能
- 标准化的分页参数传递

**技术特点**:
```typescript
interface PaginationConfig {
  total: number        // 总记录数
  currentPage: number  // 当前页码
  pageSize: number     // 每页条数
}

interface PageResult<T> {
  total: number    // 总数
  size: number     // 页大小
  current: number  // 当前页
  pages: number    // 总页数
  records: T[]     // 数据列表
}
```

**使用场景**:
- 列表数据查询
- 表格数据展示
- 搜索结果分页
- 数据加载优化

**API约定**:
- 请求参数: `currentPage`, `pageSize`
- 响应格式: `PageResult<T>`

---

### 3.8 数据字典 (Dictionary / Dict)

**定义**: 系统配置的枚举值和选项数据,用于下拉框、单选框等UI组件。

**业务含义**:
- 统一管理系统枚举值

**数据字典类型**:
```typescript
export const dictionaryType = {
  enum: EnumValue.of('枚举', 'e'),      // 手工录入

  xml: EnumValue.of('脚本', 'x')        // 脚本生成
}
```

**使用场景**:
- 下拉框选项配置
- 状态码映射
- 业务枚举管理
- 多语言支持

## 4. 权限管理术语

### 4.1 角色 (Role)

**定义**: 用户在系统中的职能定位,决定用户可访问的功能和数据范围。

**业务含义**:
- 角色是权限管理的核心概念

- 支持角色分组和层级管理


**角色类型**:

**使用场景**:
- 用户角色分配

- 数据范围限制

## 5. 工作流审核术语

### 5.1 工作流 (Workflow)

**定义**: 业务流程的自动化执行机制,定义了审批节点、流转规则和处理逻辑。

**业务含义**:
- 工作流实现业务审批流程的标准化
- 支持多级审批和条件分支
- 记录完整的审批历史

**技术特点**:
- 基于第三方工作流引擎(xflowable)
- 流程实例ID(processInstanceId)唯一标识
- 支持流程图可视化展示

**使用场景**:
- 数据集申请审核
- 数据集上传审核
- 数据公开审核
- 模型发布审核
- 模型部署审核

**相关API**:
- `/workflow/api/v1/xflowable/process/instance/history` - 查询流程进度
- `/workflow/api/v1/xflowable/task/{taskId}/approval` - 审批通过
- `/workflow/api/v1/xflowable/task/{taskId}/back` - 审批驳回

---

### 5.2 审核 / 审批 (Review / Approval)

**定义**: 对业务申请进行审查和批准的流程。

**业务含义**:
- 确保业务操作符合规范和政策

- 记录审核意见和理由

**技术特点**:

- 审核意见(message)记录审核理由

**审核类型**:
- **数据集申请审核**: 用户申请访问数据集
- **数据集上传审核**: 审核上传的数据集内容
- **数据公开审核**: 审核数据集公开申请
- **模型发布审核**: 审核模型发布到广场
- **模型部署审核**: 审核模型部署到生产环境

**使用场景**:
- 审核列表查询
- 审核详情查看
- 审核通过操作
- 审核驳回操作

---

### 5.3 审核状态 (Review Status / Approval Status)

**定义**: 审核流程的当前状态标识。

**业务含义**:
- 标识审核进度和结果
- 便于用户追踪审核状态

- **审核未通过**: 审核驳回,申请被拒绝

**使用场景**:
- 审核列表状态展示

## 📚 术语使用规范

### 优先级原则

1. **业务术语 > 技术术语**: 与业务人员沟通时优先使用业务术语
2. **中文名称 > 英文名称**: 文档和注释优先使用中文术语
3. **统一术语 > 同义词**: 避免使用同义词,选择统一的标准术语

### 命名一致性

| 概念 | 标准术语 | 避免使用 | 字段名 |
|------|----------|----------|--------|
