# 菜单优化实施说明

## 优化内容

已实现菜单优化：**对于只有一个可见页面的二级模块，点击后直接跳转到页面，无需展开收起操作**。

1. **环境配置** → 直接跳转到"环境配置"页面
2. **模型广场** → 直接跳转到"模型广场"页面

- 模型上线（4个页面：准入检测、发布审核、部署审核、部署管理）

## 技术实现

### 修改文件

- `src/components/navigation/sidebar.tsx`

### 实现逻辑

1. 在 `ModuleSection` 组件中，计算每个模块的可见页面数量（过滤掉 `show: false` 的页面）
2. 如果只有一个可见页面：
   - 直接渲染为 `Link` 组件
   - 点击后直接跳转到该页面
   - 不显示展开/收起图标
3. 如果有多个可见页面：
   - 保持原有的展开/收起逻辑
   - 显示展开/收起图标
   - 点击后展开显示子页面列表

### 代码变更

```typescript
// 计算可见页面
const visiblePages = module.pages.filter(page => page.show !== false);
const hasSinglePage = visiblePages.length === 1;

// 单个页面直接跳转
if (hasSinglePage && firstPage) {
  return <Link href={href}>...</Link>;
}

// 多个页面保持展开/收起
return <button onClick={onToggle}>...</button>;
```

## 用户体验提升

### 优化前
- 用户需要：点击一级模块 → 点击二级模块 → 点击页面（3次点击）
- 对于单个页面的模块，需要不必要的展开操作

### 优化后
- 单个页面的模块：点击一级模块 → 点击二级模块（2次点击，直接跳转）
- 多个页面的模块：保持原有逻辑（3次点击）

### 效果
- **减少点击次数**：单个页面模块从3次减少到2次（减少33%）
- **减少操作步骤**：无需展开/收起操作
- **提升导航效率**：更快的功能访问

## 注意事项

1. **页面可见性**：只有 `show !== false` 的页面才会被计算在内
2. **路由兼容性**：路由路径保持不变，不影响现有功能
3. **样式一致性**：单个页面模块的样式与多页面模块保持一致

## 后续优化建议

如果未来需要进一步优化，可以考虑：

1. **合并相似功能**：将功能相近的页面合并（如效益评估和模型评估）
2. **Tab切换**：在页面内使用Tab切换不同视图，而不是分成多个菜单项
3. **快捷入口**：在首页添加常用功能的快捷入口
