# 模型实验室和模型中心菜单优化方案

## 一、现状分析

### 1.1 当前菜单结构

#### 模型实验室（7个二级模块，20个可见页面）
```
模型实验室 🧪
├── 环境配置
│   └── 环境配置
├── 模型开发
│   ├── 机器学习模型
│   ├── 智能体模型
│   └── 数据规则模型
├── 模型训练
│   ├── 模型训练
│   └── 训练任务管理
├── 效益评估
│   ├── 效益评估
│   └── 效益评估管理
├── 模型评估
│   ├── 模型评估
│   └── 评估管理
├── 模型广场
│   └── 模型广场
└── 模型上线
    ├── 准入检测
    ├── 模型发布审核
    ├── 模型部署审核
    └── 部署管理
```

#### 模型中心（3个二级模块，6个可见页面）
```
模型中心 🏭
├── 模型库
│   └── 模型库管理
├── 模型调度
│   └── 调度管理
└── 模型监控
    ├── 模型监控管理
    └── 告警通知
```

### 1.2 存在的问题

1. **层级过深**：三级菜单结构（一级模块 → 二级模块 → 页面），用户需要多次展开才能访问功能
2. **模块划分过细**：
   - 模型实验室有7个二级模块，部分模块功能重叠（如效益评估和模型评估）
   - 模型上线模块功能分散，与模型中心职责边界不清
3. **页面冗余**：
   - 很多功能相似的页面（如效益评估和效益评估管理）
   - 详情页、编辑页等通过路由访问，不应出现在菜单中
4. **命名不统一**：
   - "模型训练"和"训练任务管理"功能重复
   - "模型评估"和"评估管理"概念混淆

### 1.3 用户使用场景分析

**模型实验室用户（开发者）主要流程：**
1. 开发模型 → 2. 训练模型 → 3. 评估模型 → 4. 发布模型 → 5. 上线审核

**模型中心用户（运维/运营）主要流程：**
1. 查看已上线模型 → 2. 配置调度 → 3. 监控运行状态 → 4. 处理告警

## 二、优化目标

1. **减少菜单层级**：从三级减少到二级（一级模块 → 页面），或合并为一级扁平化菜单
2. **合并相似功能**：将功能相近的模块合并，减少二级模块数量
3. **明确职责边界**：清晰区分模型实验室（开发环境）和模型中心（生产环境）
4. **提升导航效率**：用户最多点击2次即可访问目标功能

## 三、优化方案

### 3.1 方案一：扁平化菜单（推荐）

**核心思路**：将二级模块合并到一级模块，直接展示页面，减少一级层级

#### 模型实验室优化后结构（5个一级菜单项）
```
模型实验室 🧪
├── 环境配置
├── 模型开发
│   ├── 机器学习模型
│   ├── 智能体模型
│   └── 数据规则模型
├── 模型训练
├── 模型评估（合并效益评估和模型评估）
└── 模型广场
```

**说明**：
- 移除"模型上线"模块，将其功能整合到模型中心
- 合并"效益评估"和"模型评估"为"模型评估"
- "模型训练"和"训练任务管理"合并为一个页面，通过Tab切换

#### 模型中心优化后结构（4个一级菜单项）
```
模型中心 🏭
├── 模型库
├── 模型上线（从模型实验室移入）
│   ├── 准入检测
│   ├── 发布审核
│   ├── 部署审核
│   └── 部署管理
├── 模型调度
└── 模型监控
```

**说明**：
- 将"模型上线"从模型实验室移入模型中心，明确生产环境职责
- 模型监控合并为一个页面，通过Tab切换"性能监控"和"告警通知"

### 3.2 方案二：精简二级模块（备选）

## 四、详细优化建议

### 4.1 模型实验室优化

#### 4.1.1 合并"效益评估"和"模型评估"
**理由**：
- 两个模块功能重叠，都是对模型进行评估
- 效益评估侧重业务指标，模型评估侧重技术指标，可以在同一页面通过Tab切换

**优化后**：
- 合并为"模型评估"一个模块
- 页面内包含两个Tab：
  - Tab1：效益评估（业务指标、ROI等）
  - Tab2：技术评估（准确率、召回率、F1等）

#### 4.1.2 合并"模型训练"和"训练任务管理"
**理由**：
- 功能重复，都是管理训练任务
- 可以在一个页面中通过不同视图展示

**优化后**：
- 保留"模型训练"一个页面
- 页面内包含：
  - 创建训练任务按钮
  - 训练任务列表（支持筛选：全部/进行中/已完成/失败）
  - 训练详情查看（点击任务进入详情）

#### 4.1.3 移除"模型上线"模块
**理由**：
- 模型上线是生产环境的管理功能，应归属模型中心
- 模型实验室专注于开发、训练、评估

**优化后**：
- 将"模型上线"相关功能移至模型中心
- 模型实验室保留"发布到模型广场"功能（这是开发环境的发布）

#### 4.1.4 优化"模型开发"模块
**建议**：
- 保持三个子页面（机器学习、智能体、规则模型）
- 但可以考虑在列表页增加快速操作入口，减少跳转

### 4.2 模型中心优化

#### 4.2.1 新增"模型上线"模块
**理由**：
- 明确生产环境的模型上线流程
- 与模型实验室的开发环境形成清晰边界

**包含功能**：
- 准入检测（冒烟测试、基准测试）
- 发布审核（审核模型发布申请）
- 部署审核（审核模型部署申请）
- 部署管理（部署实例管理、版本切换、回滚）

#### 4.2.2 合并"模型监控"子页面
**理由**：
- 性能监控和告警通知是监控的两个方面，可以在同一页面展示

**优化后**：
- 保留"模型监控"一个页面
- 页面内包含：
  - Tab1：性能监控（QPS、延迟、失败率、PSI）
  - Tab2：告警管理（告警规则、告警历史、通知配置）

#### 4.2.3 优化"模型调度"
**建议**：
- 保持"调度管理"一个页面
- 页面内支持创建、编辑、查看调度任务
- 详情页和编辑页通过路由访问，不在菜单中显示

### 4.3 页面层级优化

#### 4.3.1 隐藏非菜单页面
以下页面应通过路由访问，不在菜单中显示：
- 详情页（*-detail-page.tsx）
- 编辑页（*-edit-page.tsx）
- 创建页（*-create-page.tsx）

这些页面通过列表页的操作按钮进入，不应占用菜单项。

#### 4.3.2 合并相似页面
以下页面可以考虑合并：
- "效益评估"和"效益评估管理" → 合并为一个页面，通过Tab或视图切换
- "模型评估"和"评估管理" → 合并为一个页面

## 七、风险评估

### 7.1 技术风险
- **风险**：页面合并可能影响现有功能
- **应对**：充分测试，保留原有页面作为备份，逐步迁移

### 7.2 用户体验风险
- **风险**：用户习惯现有菜单结构，调整后可能不适应
- **应对**：提供菜单使用指南，保留一段时间过渡期

### 7.3 数据迁移风险
- **风险**：合并页面可能需要迁移历史数据
- **应对**：制定详细的数据迁移方案，确保数据完整性

## 八、预期效果

### 8.1 菜单层级优化
- **优化前**：3级菜单，平均需要点击3次才能访问功能
- **优化后**：2级菜单，平均需要点击2次即可访问功能
- **提升**：导航效率提升33%

### 8.2 菜单项数量优化
- **优化前**：模型实验室7个二级模块，模型中心3个二级模块
- **优化后**：模型实验室5个一级菜单项，模型中心4个一级菜单项
- **减少**：二级模块减少约30%

### 8.3 用户体验提升
- 减少菜单展开/收起操作
- 更清晰的功能分类
- 更快的功能定位

## 九、推荐方案

**推荐采用方案一（扁平化菜单）**，理由：
1. 最大程度减少菜单层级，提升导航效率
2. 符合用户使用习惯（现代应用多采用扁平化菜单）
3. 实施难度适中，风险可控
4. 为未来功能扩展预留空间
